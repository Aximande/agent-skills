C'est quoi, un skill ?

Un skill est un fichier d'instructions expertes (SKILL.md, du simple markdown) que votre agent IA (Claude, Codex, Cursor…) charge quand la tâche correspond. Vous l'appelez par son nom (/cleanup-pass) ou en langage naturel (« nettoie ce repo »), et l'agent suit le protocole au lieu d'improviser. Ceux de ce repo ont une particularité : chacun est rodé sur de vrais projets : on sabote le code pour vérifier que le skill détecte, et chaque leçon du terrain est réécrite dedans.

Des skills pensés pour mon propre workflow avant tout, partagés tels quels : prenez, adaptez, faites-en les vôtres.

Le moteur vient d'Andrej Karpathy. Il a nommé le vibe coding (coder en acceptant ce que le modèle propose) et documenté ses pièges : assomptions silencieuses, sur-complication, abstractions gonflées, code touché sans être compris. Les 4 principes qui en découlent sont le socle de chaque skill : réfléchir avant de coder, la simplicité d'abord, des changements chirurgicaux, une exécution guidée par des critères vérifiables. Leur traduction ici : toute passe est gatée par les tests du repo cible, et ce qui ne peut pas être prouvé part en rapport, pas en commit.

Le pipeline : du vibecode au shippable

Partir d'un projet codé à l'instinct qui « marche sur ma machine » et le rendre publiable, chaque étape gatée par une preuve. (vibecode n'est pas un skill : c'est vous.)

/spec-lite

Une page de critères d'acceptation avant de vibecoder : le « quoi et pourquoi » avant le « comment ».

« Fais une spec » · « qu'est-ce qu'on construit exactement ? »

Vous obtenez : un SPEC.md d'une page, critères observables que proof-run exécute tels quels, vérifié par un agent frais.

/proof-run

Un vérificateur indépendant pilote la vraie app et prouve que la feature marche.

« Prouve que ça marche » · « vérifie cette feature dans l'app »

Vous obtenez : un verdict works/broken avec captures, embarqué dans la PR.

/safety-net

Pose un filet de tests de caractérisation sur un repo qui n'en a pas.

« Pose un filet » · « sécurise ce repo avant refacto »

Vous obtenez : des golden masters du comportement actuel, filet prouvé par sabotage.

/react-doctor

Diagnostic React/Next : pose le lint hooks, audite ce que le lint ne voit pas.

« Diagnostique ce repo React » · « pourquoi ça re-render ? »

Vous obtenez : des findings prouvés fichier:ligne (courses, effets morts), perf mesurée en re-renders.

/fluid-pass

Repasse « feel » à la Apple : gestes 1:1, springs interruptibles, reduced-motion.

« Rends cette UI plus fluide » · « rends ce design moins générique »

Vous obtenez : latences mesurées dans la vraie app, fixes gatés, mode amélioration anti-template.

/cleanup-pass

Code plus court à comportement constant : dead code retiré, docstrings posées.

« Nettoie ce repo » · « épure ce code »

Vous obtenez : des commits gatés par vos tests, aucune nouvelle failure tolérée.

/docs-pass

Un README dont chaque commande a réellement été exécutée, plus un quiz : les docs seuls doivent répondre.

« Passe les docs au propre » · « rends ce repo lisible »

Vous obtenez : docs vérifiées en commits, audit du contexte agent (CLAUDE.md).

/ship-check

Audit pré-publication : secrets (historique git compris), dépendances, RLS, surface applicative.

« Peut-on publier ce repo ? » · « passe-le en public »

Vous obtenez : un verdict GO/NO-GO par section, rapport SHIP-REPORT.md.

Les transverses

Utilisables à tout moment, indépendamment du pipeline.

/doc-ingest

PDF, Word, PowerPoint, Excel → markdown propre pour le contexte de l'agent.

« Mets ce PDF en contexte » · « ce repo entier en une page »

Vous obtenez : le document lisible par l'agent, sans perte de structure.

/llm-handover

Handover copier-coller pour passer d'une conversation LLM à un autre agent (Codex, ChatGPT, Cursor…).

« Prépare un handover » · « je passe sur Codex »

Vous obtenez : état + décisions + prochaine action, vérifié par un agent frais qui ne voit que le document.

/excalidraw-slides

Présentations Excalidraw adaptées au public et au temps de parole.

« Fais des slides Excalidraw » · « transforme ce rapport en présentation »

Vous obtenez : slides éditables, notes orales, sources, contrôle visuel.

Installer, même si c'est votre première fois

Comptez deux minutes. Choisissez votre outil ci-dessous, ou suivez le tutoriel complet, écran par écran : chaque commande, ce que vous devez voir, et le dépannage.

Prérequis (une seule fois) : un terminal (l'app Terminal sur Mac) et git (souvent déjà installé : tapez git --version pour vérifier). C'est tout. Pas besoin de savoir coder : vous copiez-collez trois lignes.
Claude Code le terminal d'Anthropic, recommandé
  1. Ouvrez le Terminal et collez : 
    # télécharge le repo puis installe les skills
git clone https://github.com/Aximande/agent-skills.git
cd agent-skills && ./install.sh
  2. Vérifiez : lancez claude dans n'importe quel projet et tapez /cleanup-pass : le skill apparaît. Vous pouvez aussi parler normalement : « nettoie ce repo ».
  3. Mise à jour plus tard : git pull dans le dossier agent-skills, rien d'autre (les skills sont des liens symboliques).
Claude app de bureau & claude.ai
  1. Téléchargez le repo (bouton Code → Download ZIP sur GitHub) et dézippez-le.
  2. Compressez le dossier du skill voulu (clic droit sur skills/cleanup-pass → Compresser).
  3. Dans Claude : Réglages → Skills → Add → Upload skill, importez le zip (captures dans le guide).
  4. Demandez ensuite en langage naturel : « nettoie ce repo avec cleanup-pass ».
Codex CLI OpenAI, et tout outil du standard agent-skills
  1. Le même ./install.sh que Claude Code installe aussi pour Codex (dossier ~/.agents/skills/, le standard agentskills.io).
  2. Codex charge le skill automatiquement quand votre demande correspond à sa description : dites simplement « nettoie ce repo ».
Cursor
  1. Le même ./install.sh génère les commandes dans ~/.cursor/commands/.
  2. Dans le chat de Cursor, tapez /cleanup-pass.
ChatGPT et tout autre chat Gemini, Le Chat…
  1. Ouvrez le skill voulu sur GitHub (ex. skills/cleanup-pass/SKILL.md), cliquez Raw, copiez tout.
  2. Collez dans la conversation avec cette consigne, puis votre demande : 
    Lis ce document et exécute-le exactement comme prescrit,
du préflight à la livraison, sans sauter d'étape.
  3. Pour un usage durable dans ChatGPT : créez un Projet (ou un GPT personnalisé) et ajoutez le fichier SKILL.md à ses fichiers ou instructions. Le skill s'applique alors à toutes les conversations du projet.
  4. Un chat ne voit pas vos fichiers locaux : collez aussi le code ou le document concerné (ou travaillez sur un dépôt connecté quand l'outil le permet).

Avec Node installé, npx skills add Aximande/agent-skills copie aussi les skills comme fichiers dans un projet, pour l'agent de votre choix.

Pourquoi « rodés » ?

Aucun skill n'est publié sur une bonne intention. Chacun suit le même cycle, et son protocole de mesure est écrit avant le premier essai.

01Grilling

Des rounds de questions serrées jusqu'à ce que chaque décision de design soit verrouillée.

02v1 + protocole

Le SKILL.md naît avec son protocole de mesure : sabotage, précision, non-régression.

03Rodage réel

Exécution sur un vrai repo, jamais un exemple jouet. On injecte des pathologies connues : le skill doit les attraper.

04Leçons encodées

Chaque défaut observé sur le terrain devient une ligne du skill. Alors seulement, on publie.

Ces skills croisent aussi d'autres travaux : le grilling de Matt Pocock, le vérificateur indépendant d'AI Builder Club, les critères d'acceptation de spec-kit, les conférences design d'Apple et le processus de review des HIG. La généalogie complète est dans la roadmap.
